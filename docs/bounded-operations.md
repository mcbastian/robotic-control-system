# Optional bounded operations and weather freshness

These opt-in controls support an explicitly armed lab session through the normal state model, OperationsManager and SOCA. They do not select a scheduler group or override readiness, solar, weather, instrument or scheduler eligibility.

Without `rcs.session.required=true`, SOCA retains its existing request behavior. With it enabled, `BoundedOperationsSession.arm(id,count,seconds)` requires engineering INIT, idle operations and termination of the previously owned task. An engineering harness can use `enterEngineering` / `leaveEngineering` to serialize its work with arming. Arming changes the state model's intent; normal controller startup does not arm a session.

IDs must be 8–80 ASCII letters, digits or underscores and cannot be reused within a controller process. Count is 1–10 attempted schedule requests, including unsuccessful selections; duration is 1–7200 seconds measured monotonically. A supervisor must call `tick` regularly to enforce elapsed expiry. The lab wrapper calls it every 250 ms. `admit` closes the SOCA admission race atomically. `sequenceEnded` stops after the final permitted request completes or fails. No automatic retry is added.

`stop` closes admission before asking genuine OperationsManager for a fast abort and engineering intent. Any active observing group follows the RCS cancellation hierarchy. Initialization is cancelled on expiry too. `status` distinguishes disarmed admission from `settled`, which requires all preceding initialization, mode and finalization tasks to be terminal. Disarming does not promise enclosure closure; the state model's weather shutdown is separate, and existing finalization may still finish. An external request transport must reject stale boot identities and quarantine pending requests before publishing readiness. The session class stores no resumable armed state.

`rcs.weather.required=WMS:25000,CLOUD:90000` requires actual EMS samples with those maximum ages in milliseconds. With the property absent, this additional guard is disabled. `rcs.weather.fresh.recovery.ms` defaults to 60000. Missing, invalid, epoch-zero, excessively future or stale samples hold WEATHER_ALERT. Recovery starts a new uninterrupted monotonic hold after any gap. Reactive WEATHER_CLEAR events cannot override that hold. No synthetic status samples or hardware commands are emitted by this guard. Weather alert/clear thresholds and other timed rules remain the configured reactive system's responsibility.

`rcs.cloud.url` optionally relocates the genuine EMS cloud input; the original file URL remains the default. `InitializeTask` supports `focus.enabled=false` for a declared fixed-focus scenario; focusing remains enabled when absent. That setting does not claim a completed focus calibration.

Causal logs distinguish `RCS_GROUP_SELECTED`, `RCS_GROUP_OUTCOME` / `RCS_GROUP_ABORTED`, `RCS_SEQUENCE_DONE`, and `RCS_HISTORY_ACK`. The last is emitted by ExecutionUpdateTask after a successful genuine DONE reply, including the group outcome flag that it reported. A failed/aborted group may therefore have a successful history acknowledgement. Parent callbacks are suppressed during abort, so that acknowledgement must be recorded by the wire task itself.

The isolated TelescopeSim integration carries hash-locked replay patches, hardware adapters and fresh scenario evidence. It enables only SOCA, retains current UTC at 1×, uses loopback endpoints, and separates its engineering harness from bounded operations acceptance. These controls are not a general unattended deployment profile or a replacement for operational safety hardware.
